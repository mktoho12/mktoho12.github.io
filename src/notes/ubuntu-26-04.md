# 家のサーバーを Ubuntu 26.04 に上げました

2026年10月に、家で使っているサーバーの Ubuntu を 24.04 LTS から 26.04 LTS に上げました
地味な作業ですが、途中で一度 GPU のドライバーが消えたので、その話を中心に残しておきます
作業は Claude（AI）と一緒に進めました

## 何をしたか

流れは次の4段階です

1. 事前確認と準備
2. 24.04 の中で最新にして再起動
3. `do-release-upgrade` で 26.04 に上げて再起動
4. 無効になった追加リポジトリを戻して確認

再起動は2回でした
作業は4時間ほどで終わり、最後はサービスもタイマーも元どおりに動いています

### 事前確認でわかったこと

追加したリポジトリ、動いているサービスとタイマー、ディスクの空き、未適用の更新を先に調べました
そこで、GPU のドライバーがすでに動いていないことに気づきました
NVIDIA のドライバーが 570 系と 580 系の2つ混ざっていて、いまのカーネル用のモジュールが入っていなかったのが原因でした
アップグレードの前に、570 系を外して 580 系だけにすることにしました

`/etc` とパッケージの一覧は、念のためバックアップしておきました

## どこで詰まったか

### autoremove で GPU のドライバーが消えた

570 系を消したあと、24.04 の中で `apt full-upgrade` と `apt autoremove` をしました
再起動してみると、`nvidia-smi` が見つからなくなっていました

調べると、`autoremove` が 580 系のドライバー本体まで消していました
580 は「ほかのパッケージのついでに入ったもの」という扱いになっていました
570 を消したことで、580 を必要とするパッケージがなくなり、「もう要らないもの」と判断されたようです

570 を消す前に `apt-get -s purge` で模擬実行はしていて、そのときは 580 が残ることを確かめていました
ただ、そのあとに続く `autoremove` までは確かめていませんでした

### 追加リポジトリが自動では戻らなかった

これは想定していたことです
`do-release-upgrade` は、追加したリポジトリを全部無効にします
新しい書式（`.sources`）で書かれていたものは `Enabled: no` が付いただけでした
古い書式（`.list`）のものは変換されず、`.list.disabled` という名前に変わっていました

### docker-compose v1 が消えた

26.04 には古い docker-compose（v1）がないので、アップグレードの途中で削除されました
compose を使っている場所はなかったので、影響はありませんでした

## どう直したか

### ドライバー

ドライバーを入れ直しました

```sh
sudo apt-get install -y nvidia-driver-580-open linux-modules-nvidia-580-open-generic-hwe-24.04
```

`apt install` で入れたので、今度は「自分で入れたもの」扱いになります
これで、この先 `autoremove` で消えることはありません
入れ直したあと、`apt-get -s autoremove` を動かして、何も消えないことを確かめました

26.04 にも同じ 580 系のパッケージがあることを先に確かめてから、本番のアップグレードに進みました

### リポジトリ

無効になったものは、`.sources` の書式で書き直しました
名前にバージョン名が入っているもの（たとえば VPN ソフトのリポジトリ）は、`noble` を `resolute` に変えました

```
Types: deb
URIs: https://example.com/ubuntu
Suites: resolute
Components: main
Signed-By: /usr/share/keyrings/example-keyring.gpg
```

書き直したファイルは、いきなり本物の設定に置かずに、別の場所で一度 `apt update` を通して、取得できることを確かめてから入れました
最後に `apt-get -s full-upgrade` と `apt-get -s autoremove` を模擬実行し、思わぬものが消えないことを見てから完了にしました

### 設定ファイルの質問

アップグレードの途中で「設定ファイルを新しいものに置き換えるか」と聞かれます
自分で手を入れている Samba の設定は「今のまま」を選びました

## AI とどう分担したか

Claude には、主に次のことを頼みました

- 事前確認（リポジトリ、サービス、ディスク、更新の数を調べる）
- 計画を立てて、先に見せてもらう
- 手順ごとのスクリプトを書く
- `apt-get -s` での模擬実行と、その結果の読み取り
- 終わったあとの動作確認と、作業ログの記録

自分でやったのは次のことです

- sudo のパスワードが要るスクリプトの実行
- `do-release-upgrade` の途中の質問への回答
- 再起動するかどうかの判断

最初に「いきなり始めない、まず計画を見せる」と決めておいたのがよかったです
スクリプトは中身を読んでから、自分の端末で実行しました

一方で、ドライバーが消えた件は、AI も自分も `autoremove` の影響を見落としていました
模擬実行は1つのコマンドだけでなく、そのあとに続くコマンドまで通しで見る必要がありました

## 次にやるときのメモ

- パッケージを消すときは、そのあとの `autoremove` まで `apt-get -s` で確かめる
- `do-release-upgrade` のあとは、追加リポジトリを書き直す前提で時間をとっておく
- バージョン名が入っているリポジトリは、新しいバージョン名に変える
- 手を入れた設定ファイルは「今のまま」を選ぶ
- WezTerm のタブで作業すれば tmux は要らなかった
- ただし再起動すると、開いているタブはすべて落ちる
